# Chat Reasoning Capability Evidence Matrix

Status: **FROZEN / APPROVED**
Reviewed: **2026-08-25**  
Approved: **2026-08-25**
Scope: native and routed **chat** reasoning controls only

This is the approved implementation source of truth. Grouped documentation identities are descriptive evidence only: they never authorize wildcard, prefix, suffix, substring, or fuzzy runtime matching. Executable capabilities require an exact reviewed ID or an explicitly documented family contract encoded as such.

## Evidence rules

1. Native provider documentation establishes documented, model-specific semantics.
2. Runtime discovery establishes availability and only the route metadata its API promises.
3. Aggregator metadata establishes capability of that aggregator route only.
4. Aggregator facts may inherit native semantics only through an exact, reviewed identity mapping.
5. Provider identity, substrings, family resemblance, another route, and absent fields in a sparse discovery API are never capability evidence.
6. `UNKNOWN` means the Gateway exposes no control for that field. It does not mean the underlying model cannot reason.

Claim provenance is local to each cell:

- **D** - official provider documentation
- **R** - runtime route metadata
- **D+R** - exact reviewed documentation plus runtime route evidence
- **U** - unknown, contradictory, or not proven
- **N/A** - the proven model semantics make the field inapplicable

`Supported`, `default`, `disable`, `mandatory`, `effort`, `budget`, output visibility, response representation, and replay are independent claims. A row-level label never upgrades an unproven cell.

- `default_effort="none"` means reasoning is off by default. It must not preselect disable after a user explicitly enables reasoning.
